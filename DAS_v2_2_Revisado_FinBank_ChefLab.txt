## 1. Escopo e arquitetura

O laboratório mantém uma aplicação monolítica modular com Node.js + Express + mysql2 e MySQL 8.0. FinBank ocupa /banco/* e demonstra três cenários de SQL Injection; ChefLab ocupa /receitas/* e demonstra XSS armazenado. A seleção do modo é controlada por cookie, e não pela URL das rotas de ataque.

## 3. Contrato de modo

| Item | Contrato |
| --- | --- |
| Cookie | lab_mode |
| Valores | vuln \| safe |
| Escopo | Path=/ |
| Leitura | middleware/mode.js lê o cookie e define req.labMode |
| Alteração | POST /api/mode com {"mode":"vuln"\|"safe"}; servidor responde Set-Cookie |
| Default no laboratório | vuln, para facilitar a demonstração; a exposição externa deve ser proibida |
| URL das rotas | Não contém o modo; query string fica reservada aos parâmetros do cenário |
| Falha/valor inválido | Tratar como vuln no ambiente de laboratório ou rejeitar explicitamente; a escolha deve ser única e documentada |

mode.js lê o cookie lab_mode e define req.labMode. POST /api/mode recebe {mode:"vuln"|"safe"} e responde com Set-Cookie. A URL fica reservada aos parâmetros do cenário. O cookie é uma convenção do laboratório, não um mecanismo de segurança.

## 4. Contrato das rotas

| Rota | Vulnerabilidade | Entrada | Modo/Oráculo | Mitigação |
| --- | --- | --- | --- | --- |
| /banco/agencias | SQLi UNION | GET cidade | 4 colunas na tabela de resultados | Prepared Statement |
| /banco/extrato | SQLi baseada em erro (didática) | GET id_conta | Erro MySQL exibido somente no vulnerável | Prepared Statement + erro genérico |
| /banco/noticia | SQLi inferencial/cega | GET id | Notícia / 404 como oráculo | Validação + Prepared Statement |
| /receitas | XSS armazenado | POST comentário | Comentário persistido | textContent ou sanitização |

4.1 /banco/agencias Modo vulnerável: SELECT de quatro colunas filtradas por cidade. Modo safe: placeholder e connection.execute(sql, [cidade]).

4.2 /banco/extrato Modo vulnerável: erro didático pode ser mostrado via err.sqlMessage. Modo safe: log interno e mensagem genérica.

4.3 /banco/noticia Oráculo de conteúdo: notícia versus 404. No modo vulnerável os erros de banco são suprimidos, para que o status seja o único canal de resposta; no modo seguro a entrada é validada antes da consulta e uma falha real de banco sobe como 500, em vez de virar um 404 que mascara indisponibilidade. Safe usa validação complementar e parametrização.

4.4 /receitas INSERT parametrizado; a vulnerabilidade está na saída, e há dois sinks de innerHTML no modo vulnerável: texto_comentario e nome_autor. Safe usa textContent nos dois.

## 6. Cenário 2 — roteiro técnico de teste

Payload previsto para o laboratório, assumindo a consulta vulnerável sobre id_conta:

98765' AND EXTRACTVALUE(1, CONCAT(0x7e, (SELECT senha FROM administradores WHERE id_admin='1'))) --%20

O %20 faz o espaço exigido pelo comentário -- chegar ao SQL após a decodificação da URL. A subquery retorna a senha sintética e o resultado é usado na expressão XPath. Com XPath inválido, ExtractValue() pode gerar XPATH syntax error contendo a expressão. A mensagem exata deve ser validada contra a versão MySQL fixada no Docker.

A documentação oficial do MySQL 8.0 registra que locator XPath inválido gera erro. O documento deve distinguir a exposição de erro do cenário completo de SQLi baseada em erro.

## 2 Lembretes Rápidos para a Hora de Programar (Node.js + mysql2)

Você não precisa alterar mais nada no documento; apenas avise a equipe sobre estes dois detalhes de implementação no Node.js para cumprir os contratos das Seções 3 e 7:

1. Execução do POST /api/reset no mysql2: Para que a rota /api/reset consiga reexecutar o script database/init.sql inteiro de uma vez (com vários DROP, CREATE e INSERT separados por ponto e vírgula), lembre-se de habilitar a flag multipleStatements: true apenas na função de reset (ou na configuração do src/config/database.js), pois o mysql2 bloqueia múltiplas queries na mesma chamada por padrão.

2. Leitura do Cookie no src/middleware/mode.js: Lembre-se de incluir o pacote cookie-parser no package.json (ou fazer um .split(';') simples em req.headers.cookie) para ler lab_mode e definir o fallback único para vuln caso o cookie ainda não exista no navegador do aluno.
